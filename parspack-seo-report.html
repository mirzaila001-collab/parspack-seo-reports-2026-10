۰راهنمای خواندن گزارش

اگر با اصطلاحات سئو آشنا نیستید، این چند تعریف کافی است تا بقیهٔ گزارش روشن شود.

Indexation
ثبت شدن صفحه در ایندکس گوگل. صفحه‌ای که index نشده در نتایج دیده نمی‌شود.
Technical SEO
خزش، indexation، redirect، XML sitemap، robots.txt، canonical، نسخهٔ www و apex، و Core Web Vitals.
robots.txt
فایلی که به خزنده‌ها می‌گوید کدام مسیر را crawl کنند و کدام XML sitemap را بخوانند.
XML sitemap
فهرست URLهایی که سایت برای کشف سریع‌تر به گوگل معرفی می‌کند.
Canonical
URL رسمی صفحه. وقتی چند نسخه وجود دارد، سیگنال رتبه باید روی یکی جمع شود.
Pillar page و topic cluster
یک صفحهٔ ستون (مثلاً هاست یا VPS) و صفحه‌های پشتیبان (ایران، آلمان، وردپرس) که با internal linking به آن وصل می‌شوند.
Keyword cannibalization
وقتی دو URL برای یک search intent رقابت می‌کنند و سیگنال رتبه بینشان تقسیم می‌شود.
Money page
صفحهٔ فروش که قرار است روی کوئری معاملاتی رتبه بگیرد؛ مثل /host و /vps.
Location page
صفحهٔ محصول برای یک لوکیشن، مثل VPS آلمان یا VPS ترکیه.
Duplicate content
متن یکسان یا near-duplicate بین URLها. Boilerplate مشترک قالب (هدر، فوتر، کارت پلن) را نباید جزو این درصد شمرد.
Boilerplate
بخش‌های تکراری قالب: منو، فوتر، ماژول قیمت و بلوک‌های ثابت طراحی. در همهٔ صفحه‌های یک قالب تکرار می‌شوند و duplicate content مقاله نیستند.
Keyword stuffing
تکرار غیرطبیعی keyword در title tag، heading یا متن. زیرمجموعهٔ over-optimization.
Scaled content abuse
سیاست اسپم گوگل (از مارس ۲۰۲۴) علیه تولید انبوه صفحه برای دستکاری رتبه، وقتی محتوا ارزش یکتا ندارد. نام سیاست گوگل است، نه برچسب خودکار این سایت.
Structured data
دادهٔ Schema.org، از جمله Organization و Product. اگر URL اشتباه باشد، entity برند را به مسیر غلط وصل می‌کند.
On-page SEO
سیگنال‌های داخل URL: title tag، meta description، heading، متن، schema، internal linking.
Off-page SEO
سیگنال‌های بیرون سایت: backlink، brand search، mention.
Helpful content
معیار سیستم‌های Core گوگل برای محتوای مفید برای کاربر، نه نوشته‌شده فقط برای موتور.
E-E-A-T
Experience, Expertise, Authoritativeness, Trust. چارچوب کیفی گوگل برای اعتماد به صفحه و برند.
Core update
به‌روزرسانی گستردهٔ سیستم‌های رتبه‌بندی گوگل.
Search Console
ابزار رسمی گوگل برای click، impression، indexation و coverage. در این نسخه وصل نیست.

۱خلاصهٔ مدیریتی

پارس‌پک برند قوی کلاد/هاستینگ با کاتالوگ تجاری گسترده و بلاگ بسیار فعال است. محدودیت فعلی کمبود محتوا نیست: indexation بلاگ، staging URL داخل structured data، و over-optimization در money page اصلی.

بازبینی ۲۴ اکتبر — دو اصلاح کارفرما
  • اصطلاح‌ها فقط واژه‌های رایج سئو هستند: technical SEO، indexation، topic cluster، money page، location page، duplicate content، keyword stuffing، keyword cannibalization، helpful content، E-E-A-T، scaled content abuse.
  • درصد شباهت ۶۵ تا ۷۷٪ کنار گذاشته شد. آن رقم Jaccard روی توکن‌های کل HTML بود و class، اسکریپت و ماژول مشترک طراحی را هم شمرده. روی متن مقاله، همان جفت‌ها حدود ۳ تا ۱۰٪ شباهت دارند.
داستان به زبان ساده

سایت از نظر محصول و ناوبری بالغ است: هاست، VPS، سرور، دامنه، CDN و PaaS در topic cluster مشخص چیده شده‌اند و بلاگ حدود ۱٬۴۴۲ پست تازه دارد.

موتور جست‌وجو هنوز سیگنال متناقض می‌بیند: XML sitemap بلاگ در robots.txt ریشه اعلام نشده، Organization schema به /new اشاره می‌کند، و www بدون 301 کنار apex روی ۲۰۰ می‌ماند.

Money page مسیر /vps با تکرار keyword و تراکم heading، over-optimization دارد.

Location pageهای VPS قالب مشترک دارند، ولی متن مقاله‌شان near-duplicate نیست. اولویت، تمیز کردن indexation و pillar pageهاست؛ نه noindex کردن صفحه‌های کشور.

سه ریسک اصلی
  • XML sitemap بلاگ در robots.txt ریشه نیست → crawl و indexation کند برای حجم اصلی محتوا.
  • Staging URL مسیر /new داخل Organization schema و Open Graph → entity برند به URL غلط وصل است.
  • Money page مسیر /vps با keyword stuffing و heading متراکم → ریسک over-optimization، جدا از location pageها.
برنامهٔ آینده در سه خط
  1. هفته ۱: 301 از www به apex · پاکسازی /new · اتصال blog sitemap به robots.txt · تعیین تکلیف /en · اصلاح Organization.
  2. هفته ۲: بازنویسی /vps و /host · Product و FAQ schema · تفکیک search intent بین /servers و /vps و /cloud-server.
  3. هفته ۳–۴: فقط جمله‌های مشترک انگلیس/فرانسه را یکتا کنید · pillar pageها را به‌روز کنید · دو تا چهار هفته معماری را ثابت نگه دارید.
دادهٔ هنوز وصل‌نشده این نسخه بدون Search Console است. با اتصال GSC می‌توان لایهٔ «کلیک / نمایش / واژه‌های رتبه» را هم پر کرد.

۵ساختار topic cluster

معماری محصول خوانا است؛ ریسک اصلی تداخل هاب‌های موازی برای نیت «خرید سرور» است.

نکتهٔ اصلی این بخش Pillar pageها وجود دارند، ولی سه URL /servers و /vps و /cloud-server هم‌زمان برای کوئری‌های نزدیک رقابت می‌کنند. قبل از صفحهٔ جدید باید search intent هر کدام جدا شود تا keyword cannibalization کم شود.

پیلارهای قوی‌تر

  • /host — هاب هاست + زیرشاخه‌های زیاد
  • /vps — هاب VPS و location pageها
  • /domain — ثبت/خرید دامنه
  • /blog — موتور محتوای آموزشی (جدا از sitemap ریشه)

هاب‌های در معرض تداخل

  • /servers در برابر /vps
  • /cloud-server در برابر هر دو
  • /dedicated-servers به‌عنوان شاخهٔ سوم
  • لینک‌های داخلی خانه با target=_blank (≈۵۵ مورد)
وزن نسبی شاخه‌های محصول در sitemap
هاب‌های موازی servers / vps / cloud-server هم‌زمان سیگنال «خرید سرور» می‌گیرند.
تفکیک search intent
  • /servers = راهنمای انتخاب نوع سرور
  • /vps = money page سرور مجازی، به‌همراه location pageها
  • /cloud-server = مدل ساعتی/ابری با تمایز قیمت و تحویل
  • هر location page فقط زیر یک pillar page بنشیند و به pillar و یکی دو صفحهٔ خواهر internal link بدهد

۶Location page و duplicate content

قالب صفحه مشترک است. متن مقاله مشترک نیست. رقم قبلی این بخش بازنشسته شد.

چرا ۶۵ تا ۷۷٪ غلط بود؟ محاسبهٔ قبلی Jaccard روی مجموعهٔ واژه‌های کل فایل HTML بود. Class name، اسکریپت و ماژول‌های ثابت طراحی (کارت پلن، منو، فوتر) در هر دو صفحه یکی‌اند و درصد را بالا می‌برند. برای duplicate content فقط متن مقاله را می‌سنجند، بعد از حذف boilerplate.
روش این بازبینی — ۲۴ اکتبر ۲۰۲۶ URLهای زندهٔ /vps/iran و /vps/foreign/{germany,turkey,canada,netherlands,sweden,england,france} به‌همراه هاب /vps. از هر صفحه فقط بلوک مقاله («… چیست؟») برداشته شد. نام کشور حذف شد. درصد = شباهت دنبالهٔ همان متن. کارت پلن، ویژگی‌ها، کامنت، محصولات مرتبط و فوتر داخل عدد نیستند.

۰٪ متن کاملاً جدا · ۱۰۰٪ near-duplicate. جفت‌های گزارش قبل بین ۳ و ۱۰٪ هستند.

۷Money page و on-page SEO

Money pageها ارزش تجاری دارند. در title tag و heading نشانه‌های keyword stuffing دیده می‌شود.

H2/H3 زیاد یعنی چه؟ تعداد heading به‌تنهایی ایراد نیست. وقتی با صدها بار تکرار یک keyword و emoji داخل title tag همراه شود، over-optimization است.

۱۰آف‌پیج و اعتبار بیرونی

در این نسخه ابزار بک‌لینک/برند سرچ وصل نیست؛ بنابراین عدد «چند لینک» ادعا نمی‌کنیم. به‌جایش: آنچه از روی سایت دیده می‌شود + چک‌لیست اجرایی برای تکمیل.

چرا این بخش کیفیت را پایین نمی‌آورد؟ حدس زدن متریک backlink بدون منبع، گزارش را ضعیف می‌کند. چک‌لیست با دادهٔ خالی بهتر از جدول ساختگی است.

۱۱آپدیت‌های گوگل و نگاشت ریسک پارس‌پک

هدف این بخش پیش‌بینی وحشت‌زده نیست؛ اتصال یافته‌های HTML به سیاست‌ها و آپدیت‌های رسمی اخیر است تا اولویت‌ها معنی‌دار شوند.

منبع زمانی خط زمانی از Google Search Status Dashboard (تا سپتامبر ۲۰۲۶) و سیاست‌های Spam / Core مستندشده. اثر روی پارس‌پک = نگاشت کیفی شواهد این ممیزی، نه ادعای «به خاطر فلان آپدیت افتادید» (برای آن GSC لازم است).

۱۳برنامهٔ ۳۰ روزه

بر اساس دادهٔ همین ممیزی — قابل بازتنظیم بعد از وصل شدن GSC.

هفته ۱ — technical SEO و indexation

  1. ۳۰۱ اجباری www → apex
  2. /new → مسیر نهایی + noindex موقت اگر لازم
  3. افزودن /blog/sitemap_index.xml به robots ریشه
  4. سیاست /en: noindex یا hreflang کامل
  5. اصلاح Organization schema و حذف ارجاع pars-next

هفته ۲ — money page

  1. بازنویسی title tag و meta description؛ emoji را از title بردارید
  2. کم کردن تکرار keyword و heading در /vps
  3. Schema از نوع Product و FAQ روی هاب‌های فروش
  4. تفکیک search intent بین /servers و /vps و /cloud-server
  5. حذف target=_blank از internal linkها

هفته ۳–۴ — location page و topic cluster

  1. بازنویسی پاراگراف‌های مشترک انگلیس و فرانسه (سفارش، سیستم‌عامل، root)
  2. بقیهٔ location pageها را noindex یا ادغام نکنید؛ متنشان جداست
  3. به‌روزرسانی pillar pageهای host و vps و domain
  4. پاکسازی post-sitemap با lastmod سال ۲۰۲۲
  5. دو تا چهار هفته معماری ثابت؛ location page جدید فقط با متن اختصاصی همان کشور

موازی — off-page (هفته ۱ و ۲ را بلوکه نکند)

  1. خروجی Links از Search Console به‌همراه brand search (پارس پک / parspack)
  2. پیدا کردن ارجاع بیرونی به /new و دامنهٔ staging
  3. بعد از هر spam update یا Core update: pillar page، location page و بلاگ را در Search Console جدا ببینید
اگر فقط ۳ کار انجام شود
  1. اتصال XML sitemap بلاگ به robots.txt
  2. حذف /new از structured data و Open Graph
  3. بازنویسی title tag و heading در /vps

۱۵روش کار، محدودیت‌ها و دادهٔ ناقص

روش ممیزی فقط‌خواندنی روی HTML عمومی، robots.txt و XML sitemap. هیچ تغییری روی سایت اعمال نشده. بازبینی ۲۴ اکتبر ۲۰۲۶ درصد duplicate content را فقط روی متن مقاله دوباره حساب کرد.
محدودیت‌ها
  • بدون Search Console: indexation واقعی، query، افت رتبه و coverage قطعی نیست.
  • بدون CrUX: page experience را نمی‌شود نمره داد.
  • درصد شباهت، شباهت دنبالهٔ متن مقاله است نه درک معنایی. قالب مشترک محصول عمداً کنار گذاشته شد.
  • رقم ۶۵–۷۷٪ نسخهٔ قبل معتبر نیست.
  • پروفایل backlink هنوز کمّی نیست.
  • نگاشت algorithm update کیفی است. بدون Search Console نمی‌شود افت را به یک update خاص نسبت داد.
برای نسخهٔ بعدی
  • Search Console: Performance ۱۶ هفته + coverage + صفحه‌های پرکلیک
  • Off-page: Links یا Ahrefs، به‌همراه brand search
  • Core Web Vitals: CrUX روی money pageها
  • بعد از Core update یا spam update: مقایسهٔ قبل و بعد روی pillar page و location page
